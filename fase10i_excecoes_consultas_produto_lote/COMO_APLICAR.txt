FASE 10I - CONSULTAS | PRODUTO + LOTE
=======================================

Escopo:
services\consultas_operacionais.py
- buscar_produto_contagem
- validar_lote_contagem

Baseline confirmado pela Fase 10A:
buscar_produto_contagem:
- 2 HTTPException

validar_lote_contagem:
- 3 HTTPException

Total: 5.

O instalador lê os status reais e aceita:
HTTP 400 -> BusinessRuleViolation
HTTP 404 -> NotFoundError
HTTP 409 -> ConflictError

Exemplos observados nas versões do SGI:
- Código obrigatório. -> 400
- Inventário não encontrado. -> 404
- Lote obrigatório. -> 400
- Lote não encontrado para este código no inventário. -> 404

O detail é preservado via AST.

Compatibilidade com 10G/10H:
routers\consultas.py pode já possuir:
- BusinessRuleViolation -> 400
- NotFoundError -> 404
- ConflictError -> 409

A 10I valida esses handlers e:
- reutiliza os corretos;
- não duplica;
- adiciona somente os que faltam.

Propagação:
O instalador monta grafo interno de chamadas do service.
Se outra função de consultas_operacionais chamar
buscar_produto_contagem ou validar_lote_contagem,
seus endpoints também são considerados afetados.

Consumidores externos:
Se outro arquivo de produção importar uma função afetada
de services.consultas_operacionais fora de routers\consultas.py,
a instalação é bloqueada antes de alterar qualquer arquivo.

Não altera:
- SQL
- conexão/UoW
- cursor
- commit/rollback
- rotas
- respostas de sucesso
- outros HTTPException do service

Pré-requisito:
Fase 10H aplicada.

Aplicar:
python .\fase10i_excecoes_consultas_produto_lote\aplicar_fase10i.py

Depois:
1. Reinicie a API.
2. python tests_e2e\regressao_final_sgi.py
3. python .\fase10a_auditoria_excecoes_dominio\auditar_fase10a.py
