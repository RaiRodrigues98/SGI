FASE 9E v3 - CORREÇÃO DO CLEANUP DE CONTAGENS
================================================

Erro da v2
----------
O arquivo real possui:

6 get_connection()
6 cursor.close()
6 conn.close()

Porém somente 5 blocos usam exatamente a forma textual:

if cursor:
    cursor.close()

if conn:
    conn.close()

O sexto fechamento possui uma estrutura textual diferente.

Correção da v3
--------------
A v3 NÃO procura mais um bloco finally literal.

Ela usa a AST do Python para localizar semanticamente:

- statements dentro de finally que executam cursor.close()
- statements dentro de finally que executam conn.close()

Aceita, por exemplo:

if cursor:
    cursor.close()

ou:

if cursor is not None:
    cursor.close()

Comentários ou outras instruções entre os fechamentos
não impedem mais a migração.

O que é preservado
------------------
Perfil real atual:
6 conexões
4 commits
8 rollbacks

Concorrência:
a quantidade encontrada no arquivo real é capturada antes.

No seu caso observado:
UPDLOCK = 7
HOLDLOCK = 7
2601 = 1
2627 = 1

Depois do patch esses mesmos números são obrigatórios.

Teste específico
----------------
A v3 foi validada também contra uma baseline sintética que reproduz:

- 6 conexões
- apenas 5 finally no formato literal antigo
- 7 UPDLOCK
- 7 HOLDLOCK
- 1 referência 2601
- 1 referência 2627

e a migração concluiu preservando todos os valores.

python .\fase9e_unit_of_work_contagens_v3\aplicar_fase9e_v3.py

Depois:

2. Execute:
python tests_e2e\regressao_final_sgi.py

Não execute a 9F antes da regressão verde da 9E.
