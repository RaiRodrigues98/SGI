FASE 10A - AUDITORIA DE EXCEÇÕES / ACOPLAMENTO HTTP
====================================================

Objetivo
--------
Mapear a situação REAL do SGI antes de alterar exceções.

Esta etapa é SOMENTE LEITURA.

Ela procura em:
- services/
- domain/
- application/

Itens:
- imports de fastapi/starlette
- raise HTTPException
- except HTTPException
- ValueError
- RuntimeError
- classes de exceção customizadas já existentes

Por que começar por auditoria?
------------------------------
Na Fase 10 não queremos fazer substituição global como:

ValueError -> DomainError

Isso seria perigoso porque ValueError pode representar:
- validação de regra de negócio;
- erro de conversão;
- erro técnico;
- programação defensiva.

Primeiro identificamos o mapa real.

Arquitetura alvo
----------------
Router
  traduz exceção da aplicação/domínio
        ↓
HTTP 400 / 404 / 409 / 422 etc.

Application / Service
  NÃO conhece FastAPI
        ↓
raise InventoryNotFound(...)
raise InvalidInventoryState(...)
raise ConflictError(...)
raise BusinessRuleViolation(...)

Domain
  contém regras e exceções sem dependência HTTP.

Importante
----------
HTTPException continua permitido nos routers.

A Fase 10 não tem como objetivo remover FastAPI da camada HTTP.

Critério 10A
------------
Dois resultados são possíveis:

RESULTADO FASE 10A: ACOPLAMENTO HTTP ENCONTRADO

ou:

RESULTADO FASE 10A: SEM ACOPLAMENTO HTTP DIRETO

Ambos são resultados válidos da auditoria.

O que define a Fase 10B será o mapa final:

HTTP imports
HTTPException raises
HTTPException handlers
ValueError/RuntimeError
Custom exception types

Executar
--------
Na raiz do SGI:

python .\fase10a_auditoria_excecoes_dominio\auditar_fase10a.py

Depois envie a saída completa.
